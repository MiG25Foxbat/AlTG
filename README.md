# Telegram UserBot — тестовый стенд сбора и суммаризации постов

Форк изначального userbot'а (реакции + автокомментарии) переработан в
локальный инструмент для теста самой идеи алертинга: читает посты из
открытых Telegram-каналов за выбранный период, фильтрует по теме и
суммаризирует через ИИ (Mistral, резерв — Groq). Веб-интерфейс — локальная страница, запускается
вместе с сервером.

Реакции и комментарии из исходного репозитория не удалены, а отключены —
код закомментирован в `UserBot.ts`, старый сценарий (`src/index.ts`) по
прежнему компилируется и доступен через `npm run legacy-bot`, если он
понадобится снова.

## Что нужно для запуска

1. Node.js 22.13+ или 23.4+ (проверялось на 22 и 24). База — Turso/libSQL
   через `@libsql/client`: для разработки достаточно локального файла
   (`DB_PATH`, без сети и без затрат), для прода — переменные
   `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN`. Бинарники прекомпилированы под
   все платформы (включая Windows) — как и раньше, без Visual Studio
   Build Tools.
2. Аккаунт Telegram и API-креды с [my.telegram.org](https://my.telegram.org)
   (API_ID, API_HASH) — как и раньше.
3. Строка сессии (`SESSION_STRING`) — та же, что уже использовалась в проекте
   ранее, либо сгенерировать заново.
4. Ключ ИИ: `MISTRAL_API_KEY` ([console.mistral.ai](https://console.mistral.ai), нужен
   активный тариф) и/или `GROQ_API_KEY` ([console.groq.com](https://console.groq.com/keys)) —
   см. «Про выбор модели» ниже.

## Установка

```bash
npm install
cp .env.example .env
# открыть .env и заполнить: API_ID, API_HASH, SESSION_STRING, MISTRAL_API_KEY, GROQ_API_KEY, SESSION_ENCRYPTION_KEY

# если SESSION_STRING ещё нет — сгенерировать:
npm run generate-session

npm run dev
```

Сервер поднимется на `http://localhost:3000` (порт меняется через `PORT` в
`.env`) и сам откроет страницу в браузере. Если авто-открытие не нужно —
выставить `NO_AUTO_OPEN=1`.

## Как пользоваться

0. При первом заходе — экран входа: зарегистрировать логин/пароль (первая
   регистрация забирает уже существующие каналы, если они были добавлены
   раньше без входа) или войти в уже созданный аккаунт. Список каналов у
   каждого аккаунта свой.
1. **Вкладка «Каналы»** — добавить один или несколько открытых каналов
   (`@username`, просто `username` или ссылка `t.me/username` — любой формат
   принимается и приводится к единому виду). Переключателем можно временно
   исключить канал из поиска, не удаляя его; «Удалить» стирает канал и всю
   историю его постов из базы. Ниже — «Приватные каналы»: подключить свой
   личный Telegram-аккаунт (телефон → код → пароль 2FA при необходимости,
   с предупреждением о риске ограничений от Telegram) и добавить оттуда
   закрытые каналы/группы, куда общий бот доступа не имеет.
2. **Вкладка «Поиск»** — выбрать период (5 мин … трое суток), ввести тему свободным
   текстом, нажать «Найти новости».
3. Пока идёт запрос — крутится индикатор загрузки (обычно 5–20 секунд:
   зависит от того, сколько постов нужно прочитать из Telegram и от скорости
   ответа ИИ).
4. Результат: короткая сводка сверху, ниже — карточки конкретных постов с
   названием канала, временем (по Москве) и ссылкой на оригинал в Telegram.

### Как устроен поиск по теме

Без трёхслойного пайплайна из основного плана проекта — сейчас два слоя,
специально для быстрого теста:

1. **Бесплатный фильтр по ключевым словам** — тема разбивается на значимые
   слова, посты с буквальным совпадением хотя бы одного слова уходят в ИИ.
   Из-за русских падежей/склонений он часто находит немного или ничего —
   это ожидаемо.
2. **Если фильтр ничего не нашёл** — в ИИ уходят вообще все посты за период
   (это видно в интерфейсе строкой «точных совпадений по словам не
   нашлось — ИИ проверил все посты за период»), и уже ИИ решает, что
   релевантно, а что нет, попутно суммаризируя отобранное.

Третий слой (семантические эмбеддинги/дедуп репостов) сознательно не
добавлен — по итогам этого теста будет понятнее, нужен ли он вообще на
таких объёмах.

## Про выбор модели — Mistral, резерв Groq

Gemini заменён: Google не отвечает на запросы с российских IP («User location
is not supported»), и локально это не обходилось даже через VPN. Сейчас
цепочка из двух провайдеров с OpenAI-совместимым API:

1. **Mistral** (`MISTRAL_MODEL`, по умолчанию `mistral-medium-latest`) — все
   запросы через одну очередь не чаще раза в `MISTRAL_MIN_INTERVAL_MS`
   (1000 мс). На 429 — ждём `retry-after` или 2 / 4 / 8 с, до трёх повторов.
2. **Groq** (`GROQ_MODEL`, по умолчанию `openai/gpt-oss-120b`) — резерв: туда
   уходит тот же запрос, если у Mistral кончились повторы, таймаут 30 с или
   любая другая ошибка. Одна попытка; не ответил — ошибка (алерт повторит
   проверку через интервал, посты не потеряются).

Ответ — JSON-объект (`response_format: json_object`), поля описаны в
системном промпте. Проверка пунктов алертов (источники, цитата, числа) от
модели не зависит. Весь код вызова ИИ — один файл
`src/modules/AiModule/llmClient.ts`, без SDK.

Если Mistral на каждый запрос отвечает 429 с заголовком
`x-ratelimit-limit-req-minute: 0` — у аккаунта не активирован тариф
(console.mistral.ai → Billing / Plans).

## Алерты через Telegram-бота

Сервис сам проверяет каналы по темам и присылает найденное в личку общему
боту. Настройка:

1. Создать бота в @BotFather, заполнить в `.env` `TELEGRAM_BOT_TOKEN`
   (локально `BOT_MODE=polling`; на Render — `BOT_MODE=webhook`,
   `PUBLIC_BASE_URL=https://…onrender.com`, `TELEGRAM_WEBHOOK_SECRET`).
2. Вкладка **«Алерты»** → «Получать алерты» → откроется бот по одноразовой
   ссылке (живёт 15 минут) → «Запустить». Если свой Telegram-аккаунт уже
   подключён на сайте (вкладка «Каналы»), достаточно написать боту `/start`.
3. Добавить темы. У каждой темы свои настройки: где искать (все каналы /
   группы / конкретные каналы), как часто проверять, присылать сразу или
   сводкой раз в N часов, с какого уровня срочности со звуком, тихие часы
   (МСК), минимум пунктов, лимит в день.

Как это работает:

- Раз в минуту планировщик берёт темы, у которых подошло время, читает
  каналы пользователя **один раз** на все его темы и отдаёт в ИИ все
  **новые** посты темы (разобранные запоминаются) — **один вызов на тему**.
  Фильтра по ключевым словам здесь нет: что относится к теме, ИИ решает по
  смыслу — подходят и новости, и анонсы, подборки, рекомендации.
  Нового нет — ИИ не вызывается.
- **Без выдумок:** модель отвечает JSON — пункт, номера постов-источников,
  дословная цитата, срочность. Код проверяет каждый пункт: источники — из
  переданных, цитата реально есть в посте, каждое число есть в цитируемых
  постах (`1,5` = `1.5`). Не прошёл — выкидывается; не прошёл ни один —
  алерт не приходит. Время и ссылки на посты подставляет сервер.
- **Громкие и тихие:** модель ставит срочность (обычное / важное / срочное),
  пользователь выбирает, с какого уровня со звуком. Громкое приходит сразу —
  даже в тихие часы, на паузе и в режиме сводки. Остальное — без звука и
  копится: после тихих часов / паузы / раз в N часов приходит одним
  сообщением.
- **Доставка:** очередь в БД (`outbox`) и отправщик с лимитами Telegram
  (1 сообщение/с в чат, ~25/с всего), повторами и обработкой блокировки бота.
- В боте: кнопки под алертом («Не релевантно», «Реже», «Отключить тему»),
  `/topics` (вкл/выкл, частота, звук), `/pause` (на час / до 09:00 МСК),
  `/settings` (сайт).
- Отвалилась личная Telegram-сессия — публичные каналы проверяются дальше,
  приватные на паузе; бот раз в сутки напоминает переподключиться.

Ограничения бесплатного Render: процесс засыпает через ~15 минут без
HTTP-запросов — в это время проверки не идут, алерты придут после
пробуждения. Диск стирается при деплое — для алертов на проде нужен Turso
(`TURSO_DATABASE_URL`). На Render ключи ИИ (`MISTRAL_API_KEY`, `GROQ_API_KEY`)
нужно вписать в Environment отдельно — локальный `.env` он не видит.

## Архитектура

```
[Каналы: SQLite, управляются через вкладку "Каналы"]
        ↓
[Fetch: UserBot.getMessagesInWindow — постранично идёт вглубь истории,
 пока не пройдёт cutoff периода; посты без текста (альбомы) отбрасываются]
        ↓
[SQLite: посты, дедуп по (канал, message_id) через UNIQUE-индекс]
        ↓
[Фильтр по ключевым словам темы (бесплатно) → при пустом результате —
 fallback на весь набор постов]
        ↓
[ИИ (Mistral → резерв Groq): отбор релевантных + суммаризация,
 одним запросом с structured JSON output]
        ↓
[Express отдаёт JSON → страница рисует сводку и карточки постов]
```

## Автотесты

```bash
npm test
```

133 теста на встроенном тест-раннере Node (`node:test`, без внешних
зависимостей) — сеть и реальные Telegram/ИИ креды не нужны:

- `keywordFilter.test.ts` — фильтр по ключевым словам: стоп-слова, регистр,
  логика «ИЛИ», пустые случаи.
- `time.test.ts` — пересчёт периодов и московского времени, отказ на
  недопустимом периоде.
- `windowMessages.test.ts` — самая нетривиальная часть: постраничный сбор
  сообщений с остановкой на границе периода. Проверено на фейковом
  постраничном источнике: правильная остановка на cutoff, отбрасывание
  постов без текста, уважение лимита `maxMessages`, корректный проход до
  конца истории канала.
- `api.test.ts` — интеграционный тест всего HTTP-слоя (`createApp`) с
  подменённым Telegram-клиентом и базой в памяти: полный сценарий
  добавления/удаления/выключения канала и запроса анализа, вплоть до самой
  границы вызова ИИ (без реального ключа тест намеренно доходит именно
  до этой точки и проверяет, что ошибка там и только там).
- Алерты: `reportValidator` (числа, цитаты, чужие источники), `messageFormat`
  (экранирование, нарезка, кнопки), `outbox` (лимиты, 429/403, повторы,
  зависшие), `bot` (привязка, токены, кнопки, пауза, webhook-секрет),
  `holdPolicy` (тихие часы, пауза, сводка, лимит), `scheduler` (весь цикл
  с фейковыми LLM и Telegram, замок экземпляра).

## Ручные сценарии для проверки в браузере

Автотесты не трогают реальный Telegram и реальный ИИ — эти шаги стоит
прогнать руками после первого запуска:

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| 1 | Первый запуск, каналов нет | Вкладка «Поиск»: кнопка «Найти новости» неактивна, есть подсказка добавить канал |
| 2 | Добавить существующий открытый канал | Появляется в списке с названием, тумблер включён |
| 3 | Добавить тот же канал ещё раз | Понятная ошибка «уже добавлен», дубликата в списке нет |
| 4 | Добавить несуществующий/опечатанный username | Ошибка «канал не найден», ничего не добавляется |
| 5 | Добавить приватный канал | Тоже «не найден» — паблик-режим, это ожидаемо |
| 6 | Ввести тему, за которую точно есть буквальные совпадения (например, тикер) | В сводке НЕТ пометки про fallback, в карточках — только реально совпавшие посты |
| 7 | Ввести тему без буквальных совпадений (например, смысловой запрос на русском) | В сводке есть пометка «точных совпадений по словам не нашлось — ИИ проверил все посты за период», ИИ всё равно находит релевантное по смыслу |
| 8 | Тема, по которой вообще ничего нет за период | Понятный пустой экран, а не пустая страница или зависание |
| 9 | Очень короткий период (5 мин) на малоактивном канале | «За выбранный период не нашлось ни одного поста» без похода в ИИ (значит, лишний токен не потрачен) |
| 10 | Выключить тумблер у единственного канала, нажать поиск | Кнопка блокируется ещё до клика с подсказкой; если всё же дернуть API напрямую — сервер вернёт понятную ошибку |
| 11 | Удалить канал | Пропадает из списка вместе со своей историей постов |
| 12 | Нажать «Найти новости» дважды подряд быстро | Кнопка блокируется на время первого запроса, повторного запроса не происходит |
| 13 | Отключить интернет на середине поиска | В интерфейсе — читаемое сообщение об ошибке, а не белый экран |
| 14 | Ни MISTRAL_API_KEY, ни GROQ_API_KEY не заданы | Понятная ошибка с прямой отсылкой к `.env`, без стектрейса в интерфейсе |
| 15 | Лимит ИИ исчерпан (429 у Mistral после повторов и у Groq) | Отдельное сообщение именно про лимит, а не общая ошибка 500 |
| 16 | Перезапустить сервер и открыть страницу заново | Список каналов и накопленные посты на месте — SQLite, не память процесса |
| 17 | Канал внезапно стал недоступен (например, забанил/сменил имя) при поиске | Этот канал помечается с ошибкой в строке метаданных, остальные каналы всё равно обрабатываются |
| 18 | «Алерты» → «Получать алерты» → «Запустить» в боте | Бот: «Готово, алерты по N темам…»; на сайте статус «Подключён» |
| 19 | Повторно открыть ту же ссылку привязки | Бот: «Ссылка устарела или уже использована» |
| 20 | Тема с интервалом 15 минут, в канал выходит пост по теме | В течение ~15 минут приходит алерт: тема, время, пункт со ссылкой на пост, кнопки |
| 21 | «Реже» под алертом → «Отменить» | «Теперь проверяю раз в …», после отмены интервал прежний (видно на сайте) |
| 22 | «Отключить тему» → «Включить обратно» | Тема выключается и включается обратно |
| 23 | `/pause` → «До утра» | Ответ с точным временем 09:00 МСК; обычные алерты копятся, громкие приходят |
| 24 | Заблокировать бота, потом разблокировать | На сайте «Вы заблокировали бота»; после разблокировки — снова «Подключён» |
| 25 | «Проверить сейчас» на вкладке «Алерты» | Подтверждённые пункты со ссылками, сколько выкинула проверка; в бот ничего не приходит |
