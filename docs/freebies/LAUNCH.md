# Задание главной сессии: халява в алерте

Ты главная сессия. Модель и уровень выбраны человеком, не меняй их. Человек ушёл и вернётся не скоро. Вопросов не задавай. Нужно решение, прими самое простое и безопасное, запиши в docs/freebies/STATUS.md строкой «Решил сам: ...» и иди дальше. Остановись, только если дальше опасно: нужен ключ, нужно что-то отправить настоящим людям, нужно тронуть боевой сервер, нужно обойти защиту сайта.

Не используй флаг пропуска проверок прав и не меняй настройки прав. Если запрос на разрешение завис, подожди, а не обходи.

## Что прочитать сначала
1. CLAUDE.md, особенно последний раздел про халяву.
2. docs/freebies/HANDOFF.md.
3. docs/handoff-telegram-alerts-bot.md, разделы про outbox, holdPolicy и Notifier.
Память прошлых сессий подтянется через claude-mem. Если она расходится с кодом, прав код.

## Шаг 0. Подготовка
- git status. Ожидаемо в дереве только подготовленное для команды: .claude/, docs/freebies/, правки CLAUDE.md и .gitignore и папка data/, её не трогай. Создай ветку freebies/1-sources-and-feed от текущего коммита и первым коммитом сохрани подготовленные файлы, без data/. Дальше коммитить будешь только ты.
- npm test. Запиши результат как исходный в STATUS. Папку недавно перенесли, поэтому если тесты падают из-за node_modules, один раз выполни npm ci и повтори. Остальное красное, найди причину и запиши, чужое не чини.
- firecrawl --status. Запиши в STATUS, работает ли и сколько кредитов осталось. Не авторизован, не пытайся входить, просто запиши, разведчик пойдёт через WebSearch и WebFetch.
- Запиши в STATUS, видны ли тебе скиллы Ponytail и firecrawl.

## Шаг 1. Контракт, пока без помощников
Напиши docs/freebies/CONTRACT.md, изучив реальный код: src/app.ts, src/db/database.ts, src/db/outboxRepo.ts, src/modules/AlertModule, src/modules/BotModule, public/app.js. Внутри:
1. Типы Deal и Source на TypeScript.
2. Таблицы базы: акции, источники, настройки халявы пользователя, отправленные алерты по акциям. Способ как в database.ts: идемпотентно.
3. Адреса API для интерфейса: общая лента с фильтром Все, Каналы, Халява, список акций, настройки по магазинам и категориям, сухой прогон.
4. Как акция проходит через существующие outbox, holdPolicy и Notifier. Свои новые файлы вместо правок чужих.
5. Раздел Ownership: для freebies-scout, freebies-backend, freebies-ui, freebies-reviewer папки и файлы, которые каждый правит. Файлы без владельца недопустимы, файлы с двумя владельцами тоже. Общие файлы database.ts, app.ts, server.ts, package.json отдай freebies-backend. Для freebies-ui это public/ и новые файлы бота для халявы.
6. Примеры данных для интерфейса в docs/freebies/mock-deals.json.
Начальная раскладка, которую можно поправить: backend это src/modules/FreebiesModule, src/db/dealsRepo.ts, новые файлы в AlertModule, src/tests/freebies*.test.ts. Разведчик это docs/freebies/SOURCES.md и DEAL_EXAMPLES.md. Проверяющий это docs/freebies/REVIEW.md.

## Шаг 2. Создание команды
Создай agent team, именно команду, а не субагентов. Четыре помощника с типами и именами: freebies-scout, freebies-backend, freebies-ui, freebies-reviewer. Модели и уровни указаны в их описаниях, не переопределяй.
Проверка: прочитай файл команды ~/.claude/teams/<имя команды>/config.json. В members должны быть четыре имени. Нет, повтори создание командой, не больше двух раз. Не вышло, запиши в STATUS и остановись.
Помощник не видит твоего разговора. В задаче каждому давай всё полностью: цель, файлы, что прочитать, как понять что готово.

## Задачи
Первый заход небольшой: Золотое яблоко и Wildberries, три самых надёжных источника.

freebies-reviewer, сразу: проверить CONTRACT.md и написать CONTRACT_OK или список исправлений. Пока нет CONTRACT_OK, backend и ui не начинают.

freebies-scout:
1. Найти 8 до 12 источников халявы. Основной инструмент Firecrawl, как описано в его инструкции. Начать с проверки сайта «Авоська» и других кандидатов из HANDOFF.md: сначала выясни, что это за сайты и подходят ли они под описание. Потом агрегаторы, официальные каналы магазинов, страницы акций, RSS. Магазины: Золотое яблоко, Wildberries, затем другие маркетплейсы. Ниши: красота, мода, зоотовары. Итог в docs/freebies/SOURCES.md с выбором трёх лучших для первого захода и причинами. Когда готовы первые пять, написать freebies-backend.
2. Собрать 15 до 20 настоящих примеров объявлений об акциях: с промокодом, с процентом, со сроком, без срока, мусор. Файл docs/freebies/DEAL_EXAMPLES.md.

freebies-backend, после CONTRACT_OK:
1. Модуль src/modules/FreebiesModule: раннер источников с интервалом на источник, случайным разбросом, условными запросами, robots.txt, один запрос к хосту за раз, повторами, автоотключением источника при ошибках.
2. Таблицы и репозиторий по контракту. Защита от дублей по ключу, срок жизни акции.
3. Разбор: сначала регулярки для промокода, скидки и срока. Нейросеть через llmClient.ts только для новых записей, прошедших фильтр. Счётчик вызовов.
4. Три источника из SOURCES.md, начиная с самых надёжных. Живой запрос к источнику не чаще раза за проверку. Остальное на сохранённых примерах.
5. Доставка: новые акции по настройкам пользователя через существующие outbox, holdPolicy и Notifier. Без повторов. Настройка «халява пробивает тихие часы», по умолчанию выключена. Реальных отправок нет, проверка на in-memory базе и сухим прогоном.
6. API для интерфейса по контракту, тесты в src/tests/freebies*.test.ts, запись в scripts.test. Эта задача идёт по мере готовности, ui ждёт адреса.

freebies-ui, после CONTRACT_OK:
1. Вкладка «Халява» в public/ на примерах из mock-deals.json.
2. Общая лента с переключателем Все, Каналы, Халява и выбор профиля при первом входе.
3. Настройки по магазинам и категориям, включая «пробивать тихие часы». Быстрые настройки в боте по образцу /topics, свой новый файл.
4. Шаблон сообщения бота об акции.
5. Когда backend отдаст адреса, переключиться с примеров на настоящие данные.

## Как идёт работа
- Каждые несколько минут обновляй docs/freebies/STATUS.md: что сделано, что идёт, что заблокировано, решения, проверенные факты.
- Не делай задачи помощников сам и не заканчивай, пока они не закончили. Начал делать за них, остановись и жди.
- Помощник упал или застрял: подтолкни, при необходимости создай замену командой. Не молчи об этом, запиши в STATUS.
- Коммит после каждого этапа, который прошёл проверку reviewer и в котором npm test и npx tsc --noEmit зелёные. Сообщения по-русски в стиле репозитория, например feat(freebies): .... Не пушить.

## Как закончить
1. Последний проход reviewer по всей ветке.
2. Заполни STATUS: что сделано и проверено, что не сделано и почему, принятые решения, как запустить и посмотреть, что осталось на следующий заход. Только проверенные факты.
3. Заверши помощников по именам. Ветку не пушить и не сливать.
